# 本地手势与地图交互优化

日期：2026-10-13。沿用用户对本地原生应用、普通摄像头、单手操作及自主实施的授权。

## 判断与方案

现有问题：15 Hz 的推理间隔额外叠加处理时间；识别信号可能在界面忙时排队；没有时间稳定判定；固定死区滤波；一次一跳的缩放和行走；缺少动作进度、暂停和输入仲裁。

比较三个路线：

1. 保留 MediaPipe Tasks 的已训练模型，改实时采集、过滤和控制层，并用已有关键点识别新增姿态。推荐；已有本地模型可复用，无新增推理网络。
2. 改 OpenCV Zoo / ONNX 手部关键点。需重做检测、跟踪、手势分类；Zoo 的相关模型同样来自 MediaPipe，没有本机比较证据证明更快。
3. 训练自定义识别模型。需要真实用户样本和独立评价数据；本次不以无数据训练宣称精度提升。

## 操作设计

| 输入 | 作用 |
| --- | --- |
| 食指 | 平滑光标；可停留选楼；所有结构模式中保持指向和选房间 |
| 拇指与食指捏合 | 接续最近的指向进行确认；拖动平移地图／室内环顾；切片、拆层、透视模式中调节当前参数 |
| 张开手掌移动 | 地图平移／室内环顾；放松或丢失手即停止 |
| 双指 V 移动 | 地图／建筑旋转，张合双指缩放；室内环顾。替代以前 V 立即复位的映射 |
| 拇指上／下 | 持续缩放；室内持续前进／后退；检查建筑时按间隔换层 |
| 握拳停留 | 打开选中建筑／进入内部；一次保持只触发一次，重新动作需松开 |
| 三指（食指、中指、无名指）停留 | 循环结构观察模式，不自动进入室内 |
| 拇指向屏幕左侧停留 | 逐级返回：室内到剖开，结构到校园；不强制复位校园视角 |
| 拇指向屏幕右侧停留 | 与握拳一样打开选中建筑／进入内部，室内时返回剖开 |
| 拇指、食指、小指伸展停留 | 暂停／恢复控制；暂停期间识别继续，保持同一姿态只切换一次 |
| 空格／暂停按钮 | 暂停地图响应，继续显示识别反馈；恢复后需要重新稳定姿态 |
| 键鼠／触控板 | 保留准确输入，补充连续按键、返回、换层、重置、捏合缩放 |

交互参数是可调整的设计默认值，不是 HCI 研究的普适结论。捏合闭合／松开采用不同阈值并按手掌宽度归一化；连续动作需约 120 ms 稳定，离散动作用约 550–850 ms 确认。One Euro 滤波减少低速抖动，快速动作提高截止频率。小范围舒适操作区、灵敏度和停留选择开关在原生面板中提供；可把舒适的食指位置设为指向中心，并恢复默认。校准后的两侧范围分别限制在可见相机坐标内。

切片时捏合横向移动控制 X 切面，上下移动控制 Y/Z；拆层时向上拖动增加层距，透视时向上拖动增加透明程度。双指张合用指尖距离与掌宽的比值计算，过滤后累计变化超过约 5% 才缩放，避免微小抖动立即改变远近。同栋楼切换结构视图保留旋转角度、缩放和水平平移；换楼／楼翼才重新建立视角，R 显式重置当前视图。

## 管线与边界

- 单手、请求 640×480、目标 30 帧采集；若驱动返回其他尺寸，按原比例缩小至 640×480 范围、不放大。LIVE_STREAM 忙时由 SDK 丢弃输入，回调只保存最新结果。
- GUI 定时取最新结果；过期结果丢弃。250 ms 没有新观测时停止连续动作。
- 捏合、三指及侧向拇指由关键点几何规则判断，不伪装成新训练模型或概率置信度。
- 捏合需满足食指弯曲角度和伸出距离条件，侧向拇指需伸直并位于掌边之外，减少与握拳混淆的机会；这仍需真人数据评价。
- 指向后的捏合确认锁定一次；观测中断或有手但姿态不明时停止动作，保留锁定。不同稳定姿态或明确无手约 220 ms 后才允许重复，避免首次加载建筑时重复进入内部。
- GUI 以帧时间积分缩放／移动，速率有界；室内移动仍通过已有碰撞检查。
- 键鼠操作暂时让出手势控制，窗口失焦停止动作；恢复需重新稳定，避免争抢视角。
- 摄像头需要用户开启，无运行时网络。显示骨架而非上传视频；提供摄像头索引选择和识别耗时／更新频率反馈。

识别 Hz 是结果更新频率，毫秒是提交图像到回调的平滑耗时，不是相机到屏幕的总延迟。30 Hz 是采集目标，不是实测结果。操作中心、灵敏度等本次只保留当前会话。

## 实施顺序与检查

1. 增加关键点解释、时间稳定判定和自适应滤波；检查输入与动作状态边界。
2. 改实时识别及最新结果传递；检查资源关闭和无新帧停止。
3. 接入连续控制、原生反馈与键鼠／触控板输入；启动原生应用检查加载和日志。
4. 更新运行说明与交付限制；提交并推送。未要求新增或运行测试套件，真人摄像头体验与性能改进不作未经实测的结论。

## 首轮检查结果

Python 文件通过语法解析；更新后的原生窗口成功加载，无启动错误，已保存上述截图。核对了本机 MediaPipe 0.10.21 的 LIVE_STREAM、异步回调及忙时流量限制 API。摄像头未开启，没有新增／运行测试套件，没有真人误触率或延迟数据。既有即时触发手势测试仍对应旧映射，旧版本 18 项通过记录不覆盖这次修改。

## 后续实施状态

继续实施前运行了现有检查：16 项通过、2 项失败，失败用例仍要求旧版即时触发与缩放映射。随后用户明确要求“先不管测试，先做”，因此这轮未修改测试，也未继续运行测试。新增了结构参数捏合控制、双指张合缩放、右拇指进入、手势暂停／恢复与视图连续性，并加强确认锁定和握拳区分。

模型权重未重新训练或替换。优化集中在现有本地模型的异步运行、关键点几何补充、时序过滤和动作控制；没有证据宣称本机识别准确率、总延迟或舒适度已达到目标。操作说明已同步到原生界面与 README，后续真人评价暂缓。

### 继续改进识别输入

核对了官方 Python 指南与本机 MediaPipe 源码：识别结果已经包含世界坐标关键点。因此接入已有的三维估计，计算手指关节角度、捏合距离和双指张合；指向、拖动和拇指方向仍使用屏幕坐标。世界坐标缺失／无效时回退图像几何，切换来源需要重新稳定姿态，防止距离量跳变触发缩放。三维关节估计随手部一起旋转，设计上比单纯图像投影更适合判断弯曲；这项预期尚未经过实际摄像头比较。

相机画面与骨架预览保留实际宽高比，取消把所有画面拉伸成 4:3 的处理；图像坐标几何按实际比例校正 Y 轴。模型姿态新增置信度迟滞：0.60 建立姿态，稳定后同一姿态在 0.45 以上可保持，低于此值立即停止。这些阈值仍是设计默认值，并非已测得的最优参数。此轮未新增或运行测试。

世界坐标是普通单目摄像头模型的估计，不能当作经过标定的真实深度。复用现有模型输出无需新增网络、模型下载或第二次推理。

### 输入交接

代码检查发现原有 600 ms 输入优先窗口可能在鼠标／触摸按住不动时结束。这轮改为跟踪应用内的按键、鼠标按钮、触摸接触和原生触控板手势起止；保持按下时手势持续让出控制，释放后保留 600 ms 交接时间，再要求姿态重新稳定。自动重复产生的按键释放不清除持键状态；输入法组合事件同样续期键鼠优先。窗口失活或打开参考图对话框时清空持键状态，避免丢失释放事件后卡在优先状态。

拖动上下文增加楼翼和楼层标识。换楼翼／楼层后，手的位置和双指张合基准重新建立，避免沿用上一视图的增量。按用户指示，此轮仍未运行测试或开启摄像头。

### 选取反馈

楼内原来由命中高度除以楼层间距推算楼层。楼板底面低于本层基准，可能落入下一层。选取路径现在直接读取命中楼板／墙／家具模型上的楼层编号，再判断命中位置是否属于室内示意轮廓。拆层间距不参与推算。

选中房间增加黄色区域高亮，使用现有示意房间多边形生成一小块网格；沿用切片／剖开裁切和拆层位置，自身不参与选取。同一房间重复确认复用高亮几何。高亮表明当前示意空间的选择，不能证明真实房间边界或官方图配准。

捏合、停留和鼠标点击共享选取入口，显示约 1.8 秒的选中名称／楼层或未命中提示；换视图清除旧提示。到达最高／最低楼层后重复换层保留房间和视图。此轮只做代码检查与实现，未运行测试，以上行为仍待实际操作验证。

## 调研依据

- [MediaPipe Python Gesture Recognizer](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer/python)：VIDEO/LIVE_STREAM 利用跟踪；实时模式异步输出，忙时忽略新输入。
- [MediaPipe Hands 原始论文](https://arxiv.org/abs/2006.10214)：检测和关键点跟踪的本地实时设计。
- [OpenCV Zoo](https://github.com/opencv/opencv_zoo)：提供 MediaPipe 系手势关键点模型，换执行器不自动等于改善此应用体验。
- [One Euro Filter 作者页面](https://gery.casiez.net/1euro/)：用速度调节低通截止频率，平衡抖动和延迟。
- [Microsoft Research 手势偏好研究](https://www.microsoft.com/en-us/research/publication/understanding-mid-air-hand-gestures-a-study-of-human-preferences-in-usage-of-gesture-types-for-hci/)：指向、直接操作等不同类型随任务有不同偏好；不是本项目姿态映射的用户验证。
- [Apple 手势设计准则](https://developer.apple.com/design/human-interface-guidelines/gestures)：连续操作的及时反馈、符合预期、替代输入，避免要求固定身体姿势。
- [Qt PinchHandler](https://doc.qt.io/qt-6/qml-qtquick-pinchhandler.html)：触摸与触控板捏合输入；本项目 Qt 6.8 API 以安装环境为准。
- [Qt 6.8 鼠标事件](https://doc.qt.io/qt-6.8/qmouseevent.html)、[原生手势事件](https://doc.qt.io/qt-6.8/qnativegestureevent.html)、[按键事件](https://doc.qt.io/qt-6.8/qkeyevent.html)：核对按下状态、手势起止与自动重复事件，用于应用内输入仲裁。
- [Qt PickResult](https://doc.qt.io/qt-6/qml-pickresult.html)：通过命中模型与场景位置选择示意房间。
